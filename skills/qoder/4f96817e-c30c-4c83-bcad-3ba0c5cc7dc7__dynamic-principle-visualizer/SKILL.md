# 原理动态解释和科普讲解（Dynamic Principle Visualizer）

## 用途

把「一个事物如何工作」做成一页能看、能点、能测的交互教学 HTML。交付物是单个自包含 .html 文件：白底、顶部为公式驱动的 SVG 动态剖面图（自动运转 + 分步点击双模式），下方六节讲解按认知链递进，自测题收尾。

成品参考：`assets/example-wave-particle-duality.html`（波粒二象性 · 双缝实验完整实现，先读它再动手）。

## 何时使用

- 用户要求「讲解 X 的原理 / X 是怎么工作的」且希望有动态图、交互或教学网页形态
- 用户要求把文章 / 讲义 / 说明书转成科普交互页面
- 触发词：原理科普、动态图解、交互教学、知识讲解网页、animated explainer

不适用：纯静态信息图（用普通图表即可）、PPT 交付（走 PPT 技能）、无讲解诉求的单纯动画。

## 核心原则：图必须自解释，关键信息必须有视觉落点

一张图天然会丢信息；动态图更严重——运动一停，部件名、当前状态、关键数值、分支和环境边界就只剩正文里才有。本技能把「图不漏信息」当作硬约束：

1. **五类视觉载体必须齐全**，各司其职：
   - **动态教具**：SVG 剖面/流程动画，自动 + 分步双模式，带颜色图例、部件编号、实时读数。
   - **静态标注图**：结构剖面，所有关键部件有编号 + 名称 + 引线；暂停、打印、脱离交互后仍可读。
   - **动态时间轴**：相位/阶段带、关键事件、各部件状态；刻度带单位。
   - **协同图**：部件 × 阶段角色矩阵 + 接力/涌现图。
   - **环境边界图**：系统边界、外部系统、输入输出流、拆掉后的失效后果。
2. **关键信息账本**：动笔前从主题/原文提取六类事实——数值与单位、顺序与相位、分支与条件、角色与职责、环境与依赖、例外/失败/代价。每条事实登记一个视觉载体，不允许只出现在正文。
3. **每张图必备七件**：标题、图例、部件/路径标签、单位与相位、当前状态或读数、读法图注、数据来源/口径。缺一项即不合格。
4. **分支不隐身**：有分支、失败、退化、例外时，主图必须画岔路，或至少配一张分支面板；不能只画 happy path。
5. **暂停可读**：任意相位定格时，标签、数值、状态仍完整；不依赖 hover、动画或颜色单独承载信息。
6. **单一事实源**：动画读数、步骤文案、映射表引用同一份相位与数据数组；不允许三处各写一套数字。
7. **原理自检**：动笔前建机制模型（目标/边界/输入输出/组成连接/状态转换/因果链/量与单位/例外简化）；交付前跑事实层、机制层、表达层三层自检。视觉完备不能替代原理完备，细节遗漏不能靠图好看掩盖。

## 一张图不够时：多动图组

当一个原理包含多个尺度、多个并行子系统，或「总览 + 局部」缺一不可时，不要把所有信息硬塞进一张图。用 2–3 张动图组成一个**动图组**：

- **角色分工**：总览图回答「在哪 / 谁和谁」；局部图回答「怎么动」；状态/时间轴图回答「何时 / 为什么」。同一事实只在一张图里做主表达，其他图只做引用。
- **一个时间总线**：所有图共用同一个 `phase` / step，由一个控制条和步骤条驱动；禁止各自 autoplay 导致不同步。
- **每张图仍要自解释**：标题、图例、标签、单位、读数；共享读数条汇总各图关键状态。
- **同步定格**：分步模式必须让所有图冻结到同一 step；不允许某张图单独跳帧。
- **布局**：主图为主，副图放右侧或下方；窄屏堆叠；最多 3 张动图，超过就拆页。
- **不同尺度要写映射**：副图若用局部时间窗，必须写清「局部 0–90° = 全局 360–450°」这类映射。

实现上只保留一个 `tick` / `render(th)`，在其中依次更新主视图、副视图和共享读数；不要让每张图各起一个 `requestAnimationFrame`。模板里的 `#eng2` / `render2(th)` 是可选挂点。

## 工作流（五步，按序执行）

### 1. 解构对象（动笔前先建模）

按 `references/methodology.md` 的六阶段框架分析目标事物，先列出：

- **关键信息账本**（六类事实 + 计划落到哪张图）
- **机制模型**（8 槽位：目标/边界/输入输出/组成连接/状态与阶段/因果链/量与单位/例外与简化）
- 静态分解：组成部件清单（MECE 分组，同层粒度一致）
- 动态流程：时间轴上的关键阶段与每个阶段各部件的状态
- 映射表：部件 × 阶段 的角色矩阵
- 环境依赖：目标事物正常运转所需的外部系统

账本建议直接写成表，交付时原样附在汇报里：

| 类别 | 要提取什么 | 典型视觉落点 |
|---|---|---|
| 数值与单位 | 阈值、比例、温度、压力、转速、尺寸 | 图内标注 / 实时读数 / 刻度轴 |
| 顺序与相位 | 先做什么、区间、周期、点火/触发时刻 | 时间轴 / 步骤条 / 相位带 |
| 分支与条件 | 命中/未命中、成功/失败、退化路径、互斥条件 | 主图岔路 / 分支面板 / 状态表 |
| 角色与职责 | 谁输入、谁处理、谁输出、谁兜底 | 静态标注图 / 映射矩阵 |
| 环境与依赖 | 供电、冷却、配置、上游数据、下游消费者 | 环境边界图 |
| 例外/失败/代价 | 反例、常见误解、代价与副作用 | 旁注卡 / 对照图 / 自测题 |

### 2. 设计图与动画（精确性 + 信息完备性）

按 `references/animation-cookbook.md` 和 `references/visual-completeness.md` 执行，硬性要求：

- **先画静态标注图，再画动画**：静态图是信息骨架（部件编号、引线、TDC/BDC、边界），动画只是时间层；不能用动画替代结构图。
- **一张动图不够就拆多视图**：按「总览 / 局部 / 状态」分工，用同一相位总线驱动 2–3 张同步动图；不要把所有机制压进一张图，也不要让多张图各自播放。
- 运动必须由数学公式逐帧驱动（如滑块曲柄公式），禁止「看起来差不多」的视觉近似。
- 动画必须带：颜色/线型图例、实时读数（相位 + 关键量 + 各部件状态）、分步定格；不能只有运动。
- 分支、失败、退化路径用岔路、虚线路径或侧栏分支面板画出来。
- 交付前用脚本数值校验运动边界（不碰撞、不穿帮、不越界）。
- 必须实现双模式：自动连续运转 + 分步点击定格（把循环切成 6–10 个关键时刻，每步配一句话讲解）。
- 动效不要跳：分步切换用 400–600ms 缓动并精确落点；点火/火焰/气流等事件用 8–15° 渐变窗口；默认周期 4–6 秒/循环，讲原理时不要默认高频。
- 运动件抵达静态落点必须交棒：落点静态文字保留，移动文字在到位前隐藏，移动卡在交棒后隐藏；不能两层文字同时可见，也不能为避让删掉落点文字。
- 运动件遮挡关卡/标签时，按实际矩形相交隐藏，不按相位窗口猜；宽包裹要同时检查相邻关卡，并用全步骤浏览器快照复核。
- 部件必须可通过 id 映射点选高亮；部件编号与静态图、部件卡一致。
- 遵循 prefers-reduced-motion。

### 3. 组装页面

复制 `assets/template.html` 为 `<主题>-explainer.html`（新版本另存独立文件，不覆盖旧版），按 `references/page-structure.md` 填充六节内容。每节至少一个视觉载体：

1. 表象观察（黑盒流程图：输入 → 黑盒 → 输出 + 边界）
2. 静态分解（**静态标注剖面图** + 编号部件卡，可点高亮）
3. 动态分析（**相位/阶段时间轴** + 状态表 + 分步演示引导）
4. 动静融合（部件×阶段映射表 + **接力/协同图**）
5. 环境场景（**环境边界图** + 外部支撑系统卡片）
6. 复盘自测（4–6 道选择题，即时反馈解析）

每节开头放一条方法论注脚（quote 样式，只写方法本身，不加作者/来源署名）；页面收尾给一句可带走的口诀式总结。

### 4. 自检（原理 + 视觉，不跑完不交付）

先跑 `references/principle-self-check.md` 的事实层 / 机制层 / 表达层自检，再跑 `references/visual-completeness.md` 与 `references/animation-cookbook.md` 末尾的 QC 清单：

- 机制链完整；相位零点与多实例相位差已说明；分支/例外/简化已声明。
- 同一事实在正文/图/表/读数/自测中口径一致。
- 账本覆盖矩阵无空项：每条关键事实都能指到具体图/表/读数。
- 每张图七件齐全；分支可见；暂停后仍可读；360 / 750 / 920px 三档无出框、无压字。
- JS 语法解析、运动边界数值校验、元素 id 完整性、STEPS 相位单调、外部依赖盘点（默认零外部依赖）。
- 全文无个人署名/来源标记；方法注脚只保留方法论。

### 5. 交付

调用 present_files 呈现 HTML 文件；汇报中给出：

- 文件路径与打开入口
- 关键信息账本 → 视觉载体的覆盖矩阵（哪条事实落在哪张图）
- 原理自检结论（机制链、相位零点与多实例差、分支/例外、简化声明、已知简化）
- 双模式与交互点的使用说明
- 校验结果（运动边界数值、id 完整性、无外部依赖）

## 设计基调（默认值，用户指定时从其指定）

- 白底浅色主题：正文 #1F1E1A，辅助 #6B695F，面板 #FBFAF6，边框 #ECEAE2，强调琥珀 #C46A0A / #EF9F27
- 字体：Microsoft YaHei；线稿笔触 #3B3A34，剖面用 45° 斜影线
- 布局：max-width 920px 单列；动画不吸顶、随内容滚动；保留「回到动画」浮动按钮
- 图例：图形色块 + 一句人话，放在主图正下方；部件编号用琥珀色圆圈，静态图/动画/卡片三处编号一致
- 实时读数：相位、关键量与各部件状态常驻在动画下方；分步定格局时冻结，不靠悬停
- 中文优先，术语保留英文原名；结尾给口诀式总结
- 方法论注脚不写个人或来源署名
