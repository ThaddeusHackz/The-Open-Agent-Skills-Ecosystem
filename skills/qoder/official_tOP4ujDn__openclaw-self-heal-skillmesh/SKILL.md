# OpenClaw 自愈执行网格

目标：让系统在故障下“自动恢复并继续推进”，而不是“报错后中断等待人工”。

## 颠覆点

把单次任务执行，升级为**有恢复能力的任务网格**：

- 失败不是终点，而是分流入口
- 任务状态可检查点恢复
- 模型/工具异常时自动降级保可用

## 适用场景

- 多步骤任务（调研→生成→发送）中途失败
- API 抖动、限流、临时超时
- 子代理并发任务存在偶发失败

## 核心机制

1. **失败分类器**：瞬时故障 / 永久故障 / 权限故障
2. **重试矩阵**：按故障类型决定重试次数与退避策略
3. **断路器**：连续失败触发熔断，防止雪崩
4. **降级链路**：强模型失败时自动回退到 fallback 模型
5. **检查点恢复**：从已完成步骤恢复，不重复全流程

## 最小落地步骤

### 1) 定义失败策略

参考 `templates/failure-policy.md`，明确：

- 哪些错误可自动重试
- 哪些错误必须人工确认
- 哪些错误直接失败退出

### 2) 建立检查点

关键步骤完成后记录：

- step 名称
- 输入摘要
- 输出摘要
- 时间戳

### 3) 配置降级链

确认：

- `agents.defaults.model.primary`
- `agents.defaults.model.fallbacks`

并为任务标注“允许降级”与“禁止降级”两类。

### 4) 设置熔断与半开探测

- 连续失败阈值：建议 3
- 熔断窗口：建议 5 分钟
- 半开探测：窗口后发起一次最小请求验证

### 5) 输出恢复报告

每次故障后输出：

- 结论（已恢复/降级运行/待人工）
- 依据（错误类型、触发条件）
- 风险（副作用、数据一致性）
- 下一步

## 边界与风险

- 外部写操作（发消息/发帖/删改）默认不自动重试
- 非幂等步骤必须人工确认后再恢复
- 熔断阈值过低会频繁降级，过高会放大故障

## 关键收益

- 复杂任务成功率显著提升
- 人工介入点从“全流程”缩减为“高风险节点”
- 故障可解释、可复盘、可持续优化
