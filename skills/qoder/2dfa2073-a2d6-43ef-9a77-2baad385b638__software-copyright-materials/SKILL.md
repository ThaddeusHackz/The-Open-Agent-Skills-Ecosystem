# 软著申报材料生成

为一款软件（个人开发者或公司）生成计算机软件著作权登记的三件套材料，并指导后续在中国版权保护中心官网的填报提交。

## 材料三件套与官方要求

| 材料 | 文件名 | 硬性要求 |
|---|---|---|
| 材料一 信息采集表 | `材料一_软件著作权登记申请信息采集表.docx` | 32 行两列表格（详见 [reference.md](reference.md)），信息一次备齐，供官网填报照抄 |
| 材料二 源程序文档 | `材料二_源程序文档.docx` | **>3000行：共 60 页 × 每页 50 行**（前 30 页 + 后 30 页）；不足 60 页交全部；**末行必须是 `}`**（大括号语言如 TS/Java；Python 等按实际末行结束）；每页页眉带软件名+版本号，右上角页码 |
| 材料三 用户操作手册 | `材料三_用户操作手册.docx` | 一般 9 章左右、不少于 15 页，含界面截图；截图处先用占位框，后续手动/脚本插图 |

三份材料**页眉统一版式**：右上角 PAGE 页码域 + 居中"软件全称 版本号"（如 `XX管理系统 V1.0`）。软件全称、简称、版本号在三份材料中必须完全一致。

## 工作流

复制此清单跟踪进度：

```
任务进度：
- [ ] 步骤1：确定软件全称/简称/版本号、开发者身份（个人/公司）
- [ ] 步骤2：运行配置向导 init_config.py 生成 soft_config.json（零改代码）
- [ ] 步骤3：生成材料一采集表（32行模板）
- [ ] 步骤4：生成材料二源程序文档（源码自动探测）
- [ ] 步骤5：生成材料三用户操作手册（章节+截图占位框）
- [ ] 步骤6：插入截图（占位框全部替换）
- [ ] 步骤7：docx 格式校验（全部通过才算完成）
- [ ] 步骤8：导出 PDF 并做 PDF 实测校验，然后指导官网填报
```

**步骤2**：运行 `python init_config.py` 交互式向导，回答一遍问题（软件名/版本/日期/申请人/环境文案/源码目录）即生成 `soft_config.json`，全部 .py 零修改。全称须以"软件/系统/平台/APP"结尾；留空字段自动以【请替换】占位，由 `verify_docs.py` 列出待补。改版本号只改这一个 JSON。

**步骤3-6**：本技能自带完整生成脚本，见 [scripts/](scripts/)（含 README 使用说明）：把 `scripts/` 拷贝到目标项目的 `项目根/scripts/soft_copyright/` 后直接运行，无需改任何 .py；源码目录、代码行数均自动探测（鸿蒙/Web/后端/移动端均适用）。

**步骤7**：docx 校验必须逐项通过（`verify_docs.py`）：

```
[材料一] 表格数=1、无残留【请填写】/【请替换】占位符、页眉OK
[材料二] >3000行=60页、每页50行、末行="}"；不足=全文提交（≤60页，末页可不足50行）、页眉OK
[材料三] 章标题数≥9、截图占位框=0（全部已插图）、页眉OK
```

**步骤8**：运行 `export_pdf.py` 导出 PDF（官网上传用 PDF），再运行 `verify_pdf.py` 做渲染结果级实测：三份 PDF **每一页**页眉均含"软件名 版本号"；材料二 PDF 每一页正文行数≥50、全文末行 `}`。注意：docx 校验通过≠PDF 合格（分页可能漂移），且 docx 手工改过内容后必须重跑导出。

## 申报主体：个人 vs 公司（差异对照）

三件套中**材料二、材料三与主体无关**（内容完全一致），差异集中在材料一采集表与官网提交流程。步骤1 确定主体后按下表执行：

| 事项 | 个人主体 | 公司主体 |
|---|---|---|
| 著作权人信息（行10） | 姓名 | 公司全称，与营业执照**一字不差**（注意全/半角括号） |
| 证件号码（行11） | 身份证号 | 统一社会信用代码（18 位） |
| 公司成立日期（行09） | 留空 | 必填（营业执照成立日期），且**须早于开发完成日期** |
| 姓名/公司名称（行25） | 本人姓名 | 公司全称 |
| 详细地址（行26） | 本人通讯地址（能收件） | 公司注册地址 |
| 联系人（行28） | 本人 | 经办人姓名 |
| 官网实名认证 | 个人实名（身份证+人脸） | **企业实名**（营业执照+法定代表人信息） |
| 官网"著作权人类型" | 个人 | 企业法人 |
| 上传主体资格证明 | 身份证正反面照片 | 营业执照副本复印件**加盖公章** |

公司主体补充注意：

1. **日期逻辑链**：公司成立日期 ≤ 开发完成日期 ≤ 首次发表日期（官网系统会校验）
2. 员工在职期间开发的软件属**职务作品**，著作权归公司；公司作为唯一著作权人时，开发方式仍勾"独立开发"
3. 企业实名认证一般 1-3 个工作日，可提前办理；同一企业账号认证一次即可申报多款软件
4. 走代理机构代办时才需加盖公章的代理委托书，公司自己在官网申报不需要
5. 脚本配置：向导中选"公司"主体时会自动追问 `公司成立日期`（须早于开发完成日期）与 `联系人`（经办人），其余配置两种主体通用

## 材料一填写规则（易错点）

1. **日期逻辑**：开发完成日期 ≤ 首次发表日期，日期格式建议 `YYYY年MM月DD日` 或 `YYYY-MM-DD`
2. **主体信息（个人 vs 公司）**：个人=著作权人填姓名、证件号码填身份证号、"公司成立日期"留空；公司=著作权人填公司全称（与营业执照一字不差）、证件号码填统一社会信用代码、"公司成立日期"必填且须早于开发完成日期（详见上方主体差异对照）
3. **开发硬件环境 ≠ 运行硬件环境**：前者是写代码用的电脑（如 `Intel Core i7 / 16GB 内存台式计算机`），后者才是运行软件的设备
4. **邮政编码必须与详细地址的区县匹配**（如杭州临安区=311300，不是 310000）
5. 编程语言只写真正的语言（如 `ArkTS`），JSON/YAML 等配置格式不要写进去
6. 采集表一经提交无法修改，但官网在线填报阶段仍可改，以官网最终提交为准

## 环境陷阱（Windows + PowerShell）

- 运行 Python 前先 `$env:PYTHONIOENCODING='utf-8'`，否则中文输出乱码
- **禁止** `python -c "含中文的长命令"` 和含中文括号路径的内联命令——一律写成 `.py` 临时脚本再执行，用完删除
- `Select-String -Pattern` 中不要用裸管道符 `|`，改用数组形式 `-Pattern "a","b"`
- 修改用户手工编辑过的 docx 时：用 python-docx 只改目标单元格（改 `paragraphs[0].runs[0].text` 保留字体），**绝不重新跑生成脚本**（会覆盖手工内容）
- docx 被 Word 打开时会出现 `~$xxx.docx` 锁文件，重新生成前须提醒用户关闭 Word
- 依赖：`pip install python-docx pywin32 PyMuPDF`（pywin32 用于导出 PDF；PyMuPDF 用于 PDF 实测校验）

## 批量转 PDF

用 `scripts/export_pdf.py`（Word COM 自动化）：`Documents.Open(src, ReadOnly=True)` → `ExportAsFixedFormat(dst, 17)`，保留原 docx。**用 `ExportAsFixedFormat` 而非 `SaveAs2`**（页眉/域保真更好）；导出前先删除同名旧 PDF（直接覆盖可能失败），旧 PDF 被 Word/阅读器占用时提示用户关闭。**官网上传用 PDF**（格式固定不被重排版），docx 留作可编辑底稿。导出后用 `scripts/verify_pdf.py` 实测每一页页眉与材料二行数。

## 官网填报指引（交付后告知用户）

1. 中国版权保护中心官网（www.ccopyright.com.cn）注册并实名认证（越早开始越好）：个人主体=个人实名（约 1-2 个工作日）；公司主体=企业实名（营业执照+法定代表人信息，约 1-3 个工作日）
2. 在线填报：软件全称/简称/版本号照抄采集表；开发方式勾"独立开发"；著作权人类型按主体选"个人/企业法人"；软件分类选"应用软件"
3. 上传材料二、材料三的 PDF + 主体资格证明：个人=身份证正反面照片；公司=营业执照副本复印件（加盖公章）
4. 证件**手机拍照即可**：四角完整、字迹清晰、无反光、纯色背景、原图不压缩；推荐手机相机"文档扫描"模式；公司营业执照公章须清晰可辨
5. 提交后约 1-2 周受理，法定审查期 60 天，通过后发电子登记证书
