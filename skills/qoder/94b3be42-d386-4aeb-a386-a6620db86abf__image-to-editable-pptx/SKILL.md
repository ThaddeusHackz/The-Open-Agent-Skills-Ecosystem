# 图片还原为可编辑 PPT

采用「复杂视觉保真 + 主要文字可编辑」的混合还原策略。
优先保留原图的整体设计质感、构图、视觉完成度和高级感，同时保证主要文字可在PPT中直接编辑。
不要将整页简单铺成一张背景图。

**默认只交付可编辑 PPTX。PNG 仅作为内部视觉校验文件，不放入交付目录、不提供图片下载链接；只有用户另行明确要求图片时才额外交付。**

## 轻量模型执行原则

你负责识图和填写布局数据，脚本负责生成文件和计算坐标。**不要从零编写 PPT 绘图程序；默认只编辑 layout.json。**

严格按 G0→G7 执行；每关达到退出条件才进入下一关。每次只处理一页或一个区域，先读原图再填字段，不凭印象补全。工具返回报错时，先修正指定的元素 id，不删除内容来通过校验。

最低能力要求：模型或可用工具能实际查看图片，并能读写本地 JSON、执行 Python。纯文本模型若没有可靠的文字及位置输入，必须先请求视觉模型或用户提供识图结果，不能保证仅靠本 Skill 还原未见过的图片。

## 固定文件与工具

以下路径相对当前任务工作目录；`<skill-dir>` 是本 Skill 的真实安装目录，不是工作目录。

| 文件 | 用途 |
| --- | --- |
| `work/source-01/` | 方向校正后的源图、坐标网格、无标注裁片与裁片位置索引 |
| `work/expected-text.json` | 从源图独立核对的文字清单，不能反向复制生成结果 |
| `work/layout.json` | 模型唯一需要维护的绘图输入 |
| `work/draft.pptx` | 构建及修正中的原生 PPT |
| `work/rendered/`、`work/compare/` | 内部渲染、边界报告、视觉对照图 |
| `output/成品.pptx` | 完成检查后唯一默认交付物 |

工具只需 Python 3.10+、`python-pptx`、Pillow。WPS 渲染另需 Windows、WPS、`pywin32` 和已检查的 harness-anything 仓库；不自动安装或运行远程代码。

## G0：锁定要求，不改变任务

从对话填写以下六项：输入文件及页序、目标比例、需要替换的准确文字、保留或修改的颜色、保留或修改的边角、交付文件名。

- 指定 16:9 → `page_size=[960,540]`；未指定 → 保持源图比例。多张图比例不同而用户未指定时先确认公共页面比例。
- 未要求改版 → 保留原配色、构图和字号层级，不自动套模板。
- 要求黑白直角 → `mode="monochrome-square"`；文字和边线黑色，底色白色，矩形与拐弯直角，无渐变和阴影。
- 不把旧任务标题、地区名称、数据或示例文案带入新任务。
- 不覆盖用户已有成品、不杀 WPS 进程、不关闭用户已打开的文稿。

**退出条件：源文件可读取，六项要求没有会改变结果的歧义。**

## G1：全图概览 → 分区放大 → 逐字核对

先执行，不手动猜测图片尺寸：

```bash
python "<skill-dir>/scripts/image_tools.py" inspect "输入图片.png" --out-dir "work/source-01"
```

1. 阅读 `source-info.json`，记录方向校正后的全图宽高。
2. 查看 `source.png`，只识别大结构：标题区、主要容器、图片区域、连接方向、脚注区。
3. 查看 `source-grid.png` 定位像素坐标；网格只用于测量，**不得放进 PPT**。
4. 按“从上到下、从左到右”的顺序查看无标注裁片，每次完成一个区域的文字、框线及连线核对。
5. 裁片坐标加索引中的全图偏移；重叠裁片是为了避免漏字，不得重复创建同一元素。
6. 数字、单位、大小写、产品名、重复标签全部逐字核对。低置信度字词单独裁切放大；仍不可辨认则提问，不猜测、不改成更合理的术语。

**退出条件：每个区域都已查看；标题、正文、注释和连接方向都有来源。**

## G2：先建立独立文字清单

按页写 `work/expected-text.json`。一条对应一个原生文本框或表格单元格；重复内容保留次数，多行写 `\n`。

```json
{"slides":[{"texts":["用户指定标题","数据源层","Kafka"],"rasterized_small_text":[]}]}
```

只有用户要求的替换才修改清单。禁止先生成 PPT，再从 PPT 抽出文字作为“预期值”。复杂图片内保留的小字在 `rasterized_small_text` 中记录区域、文字（如可辨）及原因，不能把主要标题或关键数字放进豁免区。

**退出条件：清单与源图逐项一致，用户替换已落实，无待猜文字。**

## G3：固定重建策略和几何锚点

按此顺序判断，不自由混用工具：

1. 标题、正文、关键数字、标签、注释 → 原生 `text`。
2. 边框、分隔线、基础几何图标、箭头 → `rect`、`ellipse`、`polygon`、`line`。
3. 照片、复杂插画、纹理、难拆的复杂图标 → **局部** `image`，保留质感，不把整页截图铺底或切成大图绕过限制。
4. 文字与复杂底图重叠 → 先获得不含旧字的干净局部图片，或在背景允许时覆盖旧字，再叠原生文本，避免重影；无法无痕处理时说明限制。
5. 基础表格 → 单元格 `rect+text`；有可靠数值的简单图表 → 几何形状及数字。固定生成器不支持的原生 chart 等对象见布局协议的升级路径。

在源图坐标里先确定页面内容四边界、主要容器四边界、各行中心线、列边界、箭头端点。重复结构复用相同宽高和间隔，不能逐格凭感觉估计。用户没有要求改布局时，不重排、合并区域或缩减信息。

**退出条件：每个区域确定 native 或局部 image；主要锚点和重复布局尺寸已核对。**

## G4：只填像素布局 JSON

先读取 [layout-format.md](layout-format.md)，按其字段填写 `work/layout.json`。可参考可运行的 [examples/layout.json](examples/layout.json) 与 [examples/expected-text.json](examples/expected-text.json)，但不能把示例三列布局作为所有图片的默认设计。

硬规则：

- `page_size` 是 pt；其余几何坐标、字号、线宽、内边距均为**完整源图的像素**，不要预先缩放。
- `box=[x,y,width,height]`，不是右下角坐标；每页 `source_size` 必须匹配 G1。
- 每个元素设置唯一 id，例如 `main_storage_label`；渲染报错按 id 定位。
- 框线、局部图片在前，文字在后；容器和文字是两个元素，不把文字栅格化到容器中。
- 单行标签默认 `wrap=false`，正文按原图显式换行；不靠加空格或自动缩字修正布局。
- 字体选实际安装、最接近原图的中文字体与英文字体；同一层级保持字号和字重一致。
- 简单图标可原生组合；不要让轻量模型用数百个路径点硬描复杂插画。
- `native_only=true` 用于纯原生图；有确需保留的复杂图片才设为 false。
- 保留风格时也不能忽略源图的有色背景；不要依赖生成器默认白色来替代观察。

完成一页的全部文字与图形后，再处理下一页；不要一次猜完大量页面。

**退出条件：JSON 完整，每条主要文字都对应一个 text；没有占位符、虚构字段或整页图片。**

## G5：执行固定生成器和结构校验

```bash
python "<skill-dir>/scripts/build_from_layout.py" "work/layout.json" --manifest "work/expected-text.json" --output "work/draft.pptx"
```

它负责原生形状、字体和坐标映射、去掉默认主题阴影、字段校验、画布边界及独立文字清单比对，**不会自动改写文字、缩小字号或重新布局**。只有全部结构检查通过才写 PPTX。

报错中有 `slides[i].elements[j](id)` 时只修该元素；缺字或多字则对照 G2，不篡改清单来掩盖生成错误。修正已有自产草稿才追加 `--overwrite`。

需要单独审计时：

```bash
python "<skill-dir>/scripts/audit_pptx.py" "work/draft.pptx" --manifest "work/expected-text.json" --ratio 16:9 --report "work/audit.json"
```

纯原生任务加 `--no-raster`；黑白直角加 `--monochrome --square-corners`。未要求这些限制时不要误加；原比例任务使用实际比例而不是固定 16:9。

**退出条件：生成器成功，文字缺失/多出为零，画布越界为零，图片策略符合要求。此时还不能交付。**

## G6：真实渲染 → 局部对照 → 小范围修正

```bash
python "<skill-dir>/scripts/render_with_harness.py" "work/draft.pptx" --harness-repo ".tools/harness-anything" --out-dir "work/rendered" --width 3840
```

黑白任务加 `--monochrome`，消除字体抗锯齿的彩边，保留灰阶边缘。再次渲染自己的验证文件可追加 `--overwrite`。

1. 读取 `render-report.json`：所有页 `overflow=[]`、`unmeasured_text=[]` 才通过文字边界检查。
2. 实际查看每页 PNG，先看全局比例、主次、边界、留白，再逐区放大查看文字和图标。
3. 无改版要求时，将方向校正后的源图与渲染图对照：

```bash
python "<skill-dir>/scripts/image_tools.py" compare "work/source-01/source.png" "work/rendered/draft.png" --out-dir "work/compare"
```

多页文件名为 `draft-001.png` 等。工具产生并排、叠加、差异图，均仅供内部检查；字库和抗锯齿可能产生差异，不能把像素差直接说成“保真分数”。用户改了标题或配色时，只比较未要求改变的结构和信息。

4. 按 [repair-guide.md](repair-guide.md) 的“症状→原因→改哪个字段→复核”修正。每轮只改变同一问题的字段，保留元素 id，不为消除溢出而大幅缩字。
5. 回到 G5 重新生成，再渲染检查所有受影响区域；不能只检查修正处而忽略邻近文字。

**退出条件：每页已看；没有明显错字、漏字、重影、溢出、文字遮挡、连接方向错误、位置漂移或未说明的不可编辑主要文字。**

同一问题连续三轮仍无改进，保留当前最佳草稿，说明具体 id 和限制并请求辅助；不能降低门槛或无限重试。无法运行 WPS 时必须报告“尚未完成视觉验证”，不能宣称已通过 harness 检查。

## G7：只交付最终 PPTX

将通过 G6 的草稿保存为用户要求的成品名，默认交付目录只放 PPTX。回复一至两句并提供本地文件链接，说明主要文字可编辑；有以图片保留的复杂区域或小字必须说明。不要附送内部 PNG、网格图、差异图、清单或报告。

用户另行明确要求图片时，才额外交付由最终 PPTX 渲染且已经检查的图片。不自动上传到第三方服务。

## harness-anything 与安全边界

用户提供的仓库：https://github.com/yb2460/harness-anything.git

- 当前已验证的模块为 `cli_anything/wps/utils/wps_backend.py`；调用前检查本地 checkout 与实际 API，不能把仓库理解成一键图片矢量化工具。
- 渲染脚本真实调用 `find_wps`、`open_document`、`read_document_content`，通过 WPS COM `Slide.Export` 导出内部校验图。
- 仓库位置通过 `--harness-repo` 或 `HARNESS_ANYTHING_DIR` 传入，不写死用户名或旧任务路径。
- 仓库缺失时按工具权限流程获取；不伪造 token、不关闭 TLS 校验、不盲跑安装脚本。
- 不调用仓库样例中的全局 `taskkill` 或 `app.Quit()`。已在 WPS 打开的输入文稿不得复用并关闭，应使用另存的工作副本。
- 固定生成器不支持的效果不能静默丢弃。确有必要的小范围专用重建参考 [reference.md](reference.md)，仍须执行相同质量关卡。

## 自检与评测

确定性回归：`python "<skill-dir>/tests/test_tools.py"`。测试脚本通过只证明工具逻辑，不等于轻量模型已经达到高保真。

模型评测配置在 `evals/eval.yaml`，包含独立参考图还原、指定标题替换和缺少图片时先询问三个用例；运行前使用 `skill-up validate`。配置中的 `claude_code` 是待配置引擎的示例，不表示本机已连接，也没有预选或实测某个轻量模型。

运行前确认可用引擎、视觉能力、凭据和明确的模型标识，再用 `skill-up run "<skill-dir>/evals/eval.yaml" --engine <已配置引擎> --model <已确认模型> --iteration 3`。评分脚本检查文字、几何位置、字号、箭头和仅交付 PPTX；它不代替视觉质量判断，这三个用例也不证明对所有复杂图片的泛化能力。没有真实运行的模型、结果和产物，就不得声称“轻量模型通过率”或“所有小模型都能还原”。
