# 魔镜洞察 · 3C数码市场趋势分析

## 定位

本 Skill 是魔镜洞察消费趋势分析的 3C数码行业版本，基于魔镜洞察多年行业经验沉淀的「产品创新11种方法」，从行业白皮书中精准提取 3C数码相关数据，输出结构化的市场机会洞察与战略判断。

核心目标：用数据回答"3C数码市场的机会在哪里"，同时让读者产生"想知道更多"的兴趣。

## 使用方式

安装后直接用自然语言提问，无需任何配置。Skill 自动完成报告匹配、数据提取、方法论分析和双层输出，全程约 30 至 60 秒。

### 典型提问示例

**赛道趋势分析：**
- "分析3C数码市场的最新机会"
- "消费电子赛道下半年有什么增长信号？"
- "AI数码产品市场在发生什么变化？"

**品类洞察：**
- "基于最新报告，帮我看看智能设备市场的消费人群变化"
- "小家电哪些细分品类在增长？"
- "手机配件品类的品牌格局有什么变化？"

**对比追踪：**
- "对比近两期白皮书，3C数码市场有哪些新趋势？"
- "AI数码产品赛道的主要品牌有什么变化？"

## 方法论框架

本次方法论将产品创新拆解为两个维度的交叉分析。

### 横向：四阶段产品创新流程

| 阶段 | 核心模块 | 回答的问题 |
|------|---------|-----------|
| 用户需求与市场规模 | 市场需求评估、定位研究 | 在哪里打？ |
| 产品定义及开发 | 产品创意、概念生成、产品设计、生产 | 做什么？ |
| 产品组合协同 | 套组设计 | 怎么组合打？ |
| 营销与GTM | GTM策略、线上销售 | 怎么上市？ |

### 纵向：四大方法论维度

| 方法维度 | 涵盖内容 | 回答的核心问题 |
|----------|---------|-------------|
| 市场机会点洞察 | 市场需求评估 | 机会在哪里？ |
| 产品要素组合 | 定价策略、买方分析 | 产品怎么定义？ |
| 提高连带率与复购率 | 功能测试、产品测试、销售预测 | 怎么打得更深？ |
| 沟通力研究 | 消费者沟通策略 | 怎么说得对？ |

### 分析的三层颗粒度

1. 宏观层（市场机会点洞察）：用市场需求评估和定位研究，锁定正确的事
2. 中观层（产品要素组合 + 组合协同）：通过定价、买方分析、套组设计，把事做正确
3. 微观层（连带复购 + 沟通力）：通过测试验证和消费者沟通，确保正确地卖

### 内部分析指引

围绕以下四个问题展开分析（框架名称不出现在最终输出正文中）：
- 市场机会点洞察：识别高增长潜力赛道和结构性变化信号
- 产品要素组合：跨品类要素重组、功能创新、定价策略
- 提高连带率与复购率：场景化套组、跨品类联合、复购驱动
- 沟通力研究：消费者话语体系变化、信任机制迁移

每个问题下输出 2 至 3 个核心机会点，每个机会点需包含：
- 核心数据信号（引用报告中的具体数字）
- 深层追问（以 🔍 标识，激发读者进一步了解的兴趣）

## 报告库

通过 CMS API 自动获取最新报告列表，按需从 CDN 下载匹配的 PDF，无需手动维护报告链接。

### 报告发现 API

```
GET https://cms.mktindex.com/research/notebooks/list
参数：start（年份，可选）、page_size（默认20）、page（默认1）、label=1
```

返回每条报告的 book_id、title、pubtime、desc、trade 等字段，用于匹配用户提问的赛道与时间范围。

### PDF 下载

```
https://cdn.mktindex.com/pdf/{book_id}.pdf
```

book_id 从上述 API 返回结果中获取，需 URL 编码后拼入 CDN 链接。

### 关键字段说明

- title：报告标题，用于关键词匹配
- desc：报告摘要描述，用于判断赛道覆盖范围
- book_id：PDF 下载标识符
- pubtime：发布时间，格式 YYYY-MM 或 YYYY-MM-DD
- trade：行业标签，值为 0 表示综合类报告

### 自动匹配策略

当用户提问时，按两级策略匹配报告，目标是覆盖尽可能多的历史报告：

**第一级：摘要关键词精准匹配**
1. 调用 CMS API 获取全部报告列表
2. 筛选 desc 中包含"数码"、"3C"、"电子"、"智能"关键词的报告
3. 按 pubtime 降序排列，优先选最新的

**第二级：综合白皮书正文验证（扩大历史覆盖）**
1. 若第一级命中少于 3 份，进入第二级：筛选标题含"白皮书"的多赛道综合报告（年度/季度/半年度白皮书）
2. 按 pubtime 降序逐个下载 PDF，提取文本后搜索行业关键词（"3C数码"、"3C"、"数码"、"AI 数码"）
3. 命中行业关键词的报告保留；无文字层或未命中的跳过
4. 与第一级命中报告合并去重，形成该行业的可用报告集

**报告集使用规则**
- 未指定时间：以最新报告为主数据源，其余报告用于跨期趋势对比（同比/环比、品类结构变迁）
- 指定时间（如"2024年"）：优先该时段报告，前后各取一份作对比
- 数据提取时仅聚焦 3C数码章节，不混入其他赛道数据

## 分析工作流程

全程零配置：报告列表通过 CMS API 自动获取，PDF 从 CDN 自动下载，无需用户手动提供任何文件或链接。

### Step 1：自动发现报告并匹配赛道

调用 CMS API 拉取最新报告列表：

```bash
curl -s "https://cms.mktindex.com/research/notebooks/list?start=&page_size=20&page=1&label=1" -H "User-Agent: Mozilla/5.0"
```

按「自动匹配策略」两级匹配：先筛选 desc 中含"数码"、"3C"、"电子"、"智能"的报告；若少于 3 份，再对标题含"白皮书"的综合报告逐个下载并正文验证行业关键词，获取可用报告集（按 pubtime 降序）。

### Step 2：下载 PDF 并提取数据

从 CDN 下载匹配的报告 PDF 到当前工作目录：

```bash
curl -s -o "report.pdf" "https://cdn.mktindex.com/pdf/{URL编码后的book_id}.pdf" -H "User-Agent: Mozilla/5.0"
```

使用 pypdf 将 PDF 文本提取为 UTF-8 文件后读取：

```bash
python -c "
from pypdf import PdfReader
reader = PdfReader('report.pdf')
with open('report_text.txt', 'w', encoding='utf-8') as f:
    for i, page in enumerate(reader.pages):
        text = page.extract_text()
        if text:
            f.write(f'--- Page {i+1} ---\n')
            f.write(text + '\n\n')
print(f'Done. Total pages: {len(reader.pages)}')
"
```

使用 Read 工具读取 report_text.txt 获取报告全文内容。

注意事项：
- 封面页（Page 1）通常为纯图片，无文字可提取，属正常现象
- 如果报告此前已下载过，直接复用缓存文件，无需重复下载
- **用关键词定位 3C数码章节**（搜索"3C数码"、"3C"、"数码"、"AI 数码"等章节标题关键词，不依赖固定页码），仅提取该章节数据，忽略其他赛道内容

### Step 3：方法论交叉分析

将 3C数码数据与产品创新方法论框架进行交叉映射，按四个维度逐一拆解机会点。每个机会点必须引用报告中的具体数字（增速、规模、份额等）。框架仅在此步骤内部使用，不体现在最终输出正文中。

### Step 4：双层输出

- 第一层：对话中输出精炼正文，约 300 至 500 字，简洁结论
- 第二层：生成 HTML 完整报告，写入文件，含 logo、完整分析、优先级表和转化话术

每次分析的最终产出等于对话正文加 HTML 报告文件。

## 异常处理

遇到异常情况时的处理策略（全程向用户输出进度提示，卡住时说明原因，不静默失败）：

1. **报告列表获取失败**（CMS API 无响应或超时）：等待数秒后重试一次；仍失败则使用 SKILL.md 中已验证的报告清单继续分析，并告知用户当前使用固定清单
2. **PDF 下载失败**（网络波动、CDN 不可达）：自动重试 1-2 次；仍失败则跳过该报告，明确告知用户"某报告下载失败，已跳过"，继续用其余可用报告完成分析，不中断整体流程
3. **PDF 无文字层**（图片版扫描件）：自动排除该报告，并说明该报告因无文字层不可用
4. **章节定位失败**（全文未命中行业关键词）：跳过该报告，不强行提取；若所有报告均不可用，如实告知用户当前报告库无可用数据源
5. **数据格式异常**（提取到异常字符或空文本）：忽略异常部分，保留正常内容继续分析

## 反模式与 FAQ
