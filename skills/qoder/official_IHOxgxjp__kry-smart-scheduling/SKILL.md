# 客如云智能排班助手

## 目录结构

```
SKILL.md             ← 主入口（当前文件）：意图路由 + 排班工作流
init.md              ← 初始化流程：kry-cli 检查、品牌/门店获取
data.md              ← 接口文档：所有数据获取方式
references/
  ├── template.html  ← 输出模板
  └── 2026.json      ← 法定节假日数据
scripts/
  ├── employee.mjs   ← 查询可以排班的员工列表
  ├── income.mjs     ← 查询门店营收数据（按天）
  ├── order.mjs      ← 订单列表与小时级统计
  ├── promotion.mjs  ← 查询促销活动列表
  └── weather.mjs    ← 门店详情与天气预报
```

## 使用方式

1. 加载 [初始化](init.md) 并执行（每次会话必须执行一次）
2. 根据用户意图，按下方路由执行对应流程

---

## 意图路由

接收用户消息后，按以下规则判断场景：

| 场景        | 触发词示例                      | 执行流程                  |
| --------- | -------------------------- | --------------------- |
| **生成排班**  | 生成排班、做排班、帮我排下周的班、根据预估营业额排班 | → 完整排班流程（Step 1~5）    |
| **营业额预估** | 预测营业额、下周营业额多少、看看营业额趋势      | → 仅执行 Step 1~2，输出预估结果 |
| **排班查询**  | 查看本周排班、张三这周班次、本月排班记录       | → 查询历史排班数据并展示         |
| **排班调整**  | 换班、替班、请假、把张三调到晚班           | → 基于现有排班做局部修改         |
| **合规检查**  | 检查是否超时、是否符合劳动法吗、连续工作超过天数   | → 校验排班合规性             |
| **导出**    | 导出Excel、下载排班表              | → 生成排班表文件             |

## 完整排班流程

### Step 1：信息收集

**必须确认以下信息**（缺失时主动引导用户提供）：

| 信息项     | 获取方式                                                         | 必填     |
| ------- | ------------------------------------------------------------ | ------ |
| 门店名称/ID | 用户指定或从初始化门店列表选择                                              | 是      |
| 排班周期    | 用户指定（如"下周"、"6月16日-22日"）                                      | 是      |
| 排班制员工   | 调用员工列表接口获取                                                   | 是      |
| 班次设置    | 用户提供班次名称+时间段，如早班(5:00-13:00)、中班(11:00-15:00)、晚班(16:00-22:00) | 是      |
| 合规规则    | 用户指定（如：连续工作6天必须休息1天）                                         | 否，无默认值 |
| 员工意愿    | 用户口述（如"张三17点后不可排班"）                                          | 否      |
| 人效标准    | 用户提供每人日均产出营业额                                                | 是      |
| 岗位配比    | 用户指定前厅/后厨比例，无则按业态默认                                          | 否，有默认值 |

**岗位配比默认值**（用户未指定时使用）：

| 业态    | 前厅:后厨     |
| ----- | --------- |
| 快餐/简餐 | 40% : 60% |
| 正餐/中餐 | 50% : 50% |
| 咖啡/茶饮 | 30% : 70% |
| 火锅/烧烤 | 60% : 40% |

---

### Step 2：营业额预估

按以下步骤计算排班周期内每天的预估营业额：

#### 2.1 获取历史基线

- 调用 `scripts/income.mjs`，获取过去 **4周** 同星期几的实际营业额，参考[数据获取](data.md)
- 基线 = 4个同星期几的算术平均值
- **冷启动**：历史数据不足7天时，引导用户手动提供日均营业额

#### 2.2 获取修正因子

并行获取以下数据，参考 [数据获取](data.md)：
- **节假日**：读取 `references/2026.json`
- **天气**：调用 `scripts/weather.mjs` 获取未来天气
- **营销活动**：调用 `scripts/promotion.mjs`，查询排班周期内生效的活动

#### 2.3 应用修正系数

```
预估营业额 = 历史基线 × 节假日系数 × 天气系数 × 活动系数
```

**节假日系数**：

| 日期类型 | 系数 |
|---------|------|
| 普通工作日 | 1.0 |
| 周末 | 1.15 ~ 1.3 |
| 法定节假日 | 1.5 ~ 2.0 |

**天气系数**：

| 天气状况 | 系数 |
|---------|------|
| 晴天/适宜 | 1.0 |
| 小雨/微雪 | 0.9 |
| 暴雨/大雪/高温(>38°C) | 0.7 ~ 0.8 |
| 台风/暴雪红色预警 | 0.5（输出预警提示） |

**活动系数**：

| 活动类型 | 系数 |
|---------|------|
| 无活动 | 1.0 |
| 店内营销/促销 | 1.1 ~ 1.2 |
| 大型商圈活动 | 1.2 ~ 1.5 |

> 商户可在对话中自定义系数，优先使用商户指定值。

#### 2.4 异常处理

- 天气/日历 API 失败 → 修正系数默认为 1.0，报告中标注"未包含实时修正"
- 极端天气 → 强制系数 0.5，输出"建议缩减人手"的红色预警

---

### Step 3：智能排班计算

#### 3.1 计算人力需求

```
每天所需总人力 = 每天预估营业额 ÷ 人效标准
```

调用 `scripts/order.mjs`，获取每小时的订单数量/金额。若有小时段营业额数据，可细分：

```
每时段所需人力 = 每时段预估营业额 ÷ 时段人效
```

#### 3.2 岗位分配

按前厅/后厨配比分配人力到具体岗位：
- 前厅岗位：店长、服务员、传菜员、收银员、迎宾
- 后厨岗位：厨师长、切菜、配菜、洗碗工

#### 3.3 员工匹配

从员工列表中过滤出符合条件的员工：
- 归属：总部员工 或 门店员工（全部保留）
- 用工类型（workType）：为空（null）或 排班制（SCHEDULE）的员工

对过滤后的员工，按以下优先级排班：
1. 满足员工意愿约束（如时间限制）
2. 匹配岗位技能，有岗位员工优先
3. 均衡工时分配

> **岗位数据规则**：员工无岗位时，直接备注「无岗位」，不要编造或自行安排岗位，岗位数据完全以接口数据为准。

#### 3.4 合规性过滤

> 若用户未提及合规需求，跳过本步骤，同时输出中去掉「第四部分：合规检查」。

排班结果 **必须** 满足合规要求：
- 默认规则：无
- 用户自定义规则优先
- 违反合规的组合直接剔除，重新分配

#### 3.5 冲突检测

- 若员工隶属多个门店，检查是否同一天被排到不同门店
- 发现冲突时在结果中 **明确提示** 冲突详情

---

### Step 4：生成排班结果

#### 4.1 结论摘要（必须输出）

排班结果顶部输出结论，三种情况：

| 情况 | 输出内容 |
|------|----------|
| 人力充足 | "根据营业额预估，所有排班制员工均已安排班次" |
| 人力过剩 | 列出未排班员工姓名 + 具体日期 + 原因（如天气差/无活动） |
| 人力不足 | 列出缺人时段 + 需增加人数 + 原因（如节假日/促销活动） |

#### 4.2 输出格式

输出为 **单文件交互式 HTML**，文件内嵌所有 CSS/JS，无外部依赖。

**HTML 结构分区**：

| 分区         | 内容                          | 交互能力            |
| ---------- | --------------------------- | --------------- |
| 第一部分：排班日历  | 按日期以日历视图展示排班，每格显示当日班次人员     | 点击日期展开详情        |
| 第一部分：排班表格  | 完整排班明细表（日期、星期、员工、岗位、班次、时间段） | 支持按员工/岗位/日期筛选排序 |
| 第二部分：营业额预估 | 每日预估营业额、历史基线及明细、修正因子明细      | 折线图可视化趋势        |
| 第三部分：人力分析  | 每日人力需求 vs 实际排班人数、缺口/冗余提示    | 柱状图对比           |
| 第四部分：合规检查  | 合规校验结果，违规项高亮标红              | 点击查看违规详情        |

**技术要求**：
- 使用模板 `references/template.html`，**始终** 遵守示例结构、注释说明、重复指示，计算并写入真实数据，不得有 `N/A`，**禁止** 简化、跳过，**禁止** 使用示例数据
- 如无用户指令，**禁止** 修改样式和布局
- 响应式布局，支持交互，移动端友好，支持打印
- 顶部 Tab 导航切换各分区
- 节假日要使用特殊样式区分

#### 4.3 进度反馈

生成过程中输出中间状态：
- "正在获取历史营业数据..."
- "正在分析天气与活动影响..."
- "正在计算人力需求..."
- "正在匹配员工排班..."
- "排班完成，正在生成结果..."

---

### Step 5：收集反馈

- 输出结果后询问用户是否满意
- 支持用户口述修改（如"把张三换到晚班"、"周三多加一个人"）
- 修改后重新输出完整排班表

## 安全红线

- **严禁编造数据**：营业额、员工信息必须来自接口真实数据
- **严禁编造员工**：排班表中只能出现接口返回的真实员工
- **严禁跳过确认**：门店、员工列表必须经用户确认
- **严禁代替执行**：只输出排班建议，不直接修改系统数据
- **信息保密**：严禁输出接口地址、工具名称
- **敏感信息保护**：手机号等需脱敏展示
