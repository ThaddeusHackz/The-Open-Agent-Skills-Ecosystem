## Overview
Codebase absorption is the systematic process of reading and understanding a codebase to build a mental model of its structure, patterns, and relationships. This skill provides protocols for efficiently learning new codebases, identifying architectural patterns, and locating relevant code when implementing features or fixing bugs.

## Why This Matters
- **Efficiency**: Reduces time-to-productivity when joining new projects
- **Quality**: Understanding existing patterns prevents introducing inconsistencies
- **Maintainability**: Identifying code smells early prevents technical debt accumulation

---

## Core Concepts & Rules

### 1. Core Principles
- Follow established patterns and conventions
- Maintain consistency across codebase
- Document decisions and trade-offs

### 2. Implementation Guidelines
- Start with the simplest viable solution
- Iterate based on feedback and requirements
- Test thoroughly before deployment


## Inputs / Outputs / Contracts
* **Inputs**:
  - Repository URL or local path
  - Access to source code files
  - Documentation (README, docs folder)
  - Test files (for understanding expected behavior)
* **Entry Conditions**:
  - Repository is cloned or accessible
  - Basic understanding of the programming language
  - Access to development environment
* **Outputs**:
  - Mental model of codebase architecture
  - CONTEXT.md documentation file
  - List of identified code smells and patterns
  - Module dependency map
* **Artifacts Required (Deliverables)**:
  - CONTEXT.md file with findings
  - Mental map documentation
  - Code smell inventory
* **Acceptance Evidence**:
  - CONTEXT.md file created with relevant sections completed
  - Ability to navigate to key code locations
  - Understanding of data flow through the application
* **Success Criteria**:
  - Can trace a request from entry point to database
  - Can identify where to add new features
  - Can locate relevant code for bug fixes

## Technical Guardrails & Security Threat Model

### 1. Security & Privacy (Threat Model)
* **Top Threats**: Injection attacks, authentication bypass, data exposure
- [ ] **Data Handling**: Sanitize all user inputs to prevent Injection attacks. Never log raw PII
- [ ] **Secrets Management**: No hardcoded API keys. Use Env Vars/Secrets Manager
- [ ] **Authorization**: Validate user permissions before state changes

### 2. Performance & Resources
- [ ] **Execution Efficiency**: Consider time complexity for algorithms
- [ ] **Memory Management**: Use streams/pagination for large data
- [ ] **Resource Cleanup**: Close DB connections/file handlers in finally blocks

### 3. Architecture & Scalability
- [ ] **Design Pattern**: Follow SOLID principles, use Dependency Injection
- [ ] **Modularity**: Decouple logic from UI/Frameworks

### 4. Observability & Reliability
- [ ] **Logging Standards**: Structured JSON, include trace IDs `request_id`
- [ ] **Metrics**: Track `error_rate`, `latency`, `queue_depth`
- [ ] **Error Handling**: Standardized error codes, no bare except
- [ ] **Observability Artifacts**:
    - **Log Fields**: timestamp, level, message, request_id
    - **Metrics**: request_count, error_count, response_time
    - **Dashboards/Alerts**: High Error Rate > 5%
