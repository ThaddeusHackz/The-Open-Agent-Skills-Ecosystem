# AI内容永动机调度器 (Schedule-Content)

## 系统概述

这不是一篇"讲道理"的文章，而是一份可以直接上手练习的技能手册。

如果一套方法只能看懂，那它是知识；如果一套方法可以照着做，那它才是技能。

Dan Koe 在 Greg Isenberg 的播客中，系统性分享了他的 AI 内容创作飞轮。本系统把 Dan Koe 的「AI 内容永动机」完全拆解为 4 个可复用 Skills。

## 核心理念

AI 不会自动帮你成为更好的创作者，除非你已经在用"系统"的方式创作。

当你真正掌握这 4 个 Skills，你做的就不再是内容，而是——"一套可以不断产出内容的能力。"

## 四个 Skill 概览

### Skill 1｜Content-Judge
- **作用**：把模糊的"感觉"，训练成稳定可复用的判断力
- **目标**：不是学写作，而是学「判断什么值得写」
- **触发场景**：刷到高赞内容，想分析为什么会火

### Skill 2｜Content-Clarify
- **作用**：解决「我知道我要写什么，但就是写不出来」
- **目标**：在写作前强制澄清关键决策变量
- **触发场景**：打开文档却不知道从哪写、想法多但逻辑混乱

### Skill 3｜Content-Architect
- **作用**：一个好想法，只消耗一次脑力
- **目标**：将已验证观点升级为"可长期复用的核心内容"
- **触发场景**：短内容数据不错、观点被反复引用

### Skill 4｜Content-Build
- **作用**：不是多写，而是「把写过的用到极致」
- **目标**：将一份母内容最大化利用，实现一次思考、多次分发
- **触发场景**：已完成长文、视频或 Newsletter

## 正确使用顺序（必须牢记）

⚠️ **顺序一旦错，系统就会失效**

唯一正确顺序是："拆解 → 想清楚 → 写一次 → 用到极致"

### 调度流程

当用户提出内容创作相关请求时：

1. **评估阶段**：判断用户当前处于创作流程的哪个阶段
2. **调度决策**：根据阶段调用相应的 skill
3. **执行引导**：按照正确顺序引导用户使用 skills

### 阶段判断标准

**阶段 1 - 拆解阶段**
- 用户提到：分析爆款、学习结构、为什么火
- 调用：`Content-Judge`

**阶段 2 - 澄清阶段**
- 用户提到：不知道写什么、逻辑混乱、写作卡壳
- 调用：`Content-Clarify`

**阶段 3 - 构建阶段**
- 用户提到：验证过的观点、要升级内容、写母内容
- 调用：`Content-Architect`

**阶段 4 - 裂变阶段**
- 用户提到：已完成内容、要复用、多平台分发
- 调用：`Content-Build`

## 系统化使用指南

### 完整流程示例

1. **用户刷到爆款内容**
   → 调用 `Content-Judge` 拆解结构
   → 判断是否值得复用

2. **确定要创作内容**
   → 调用 `Content-Clarify` 澄清写作条件
   → 回答6个核心问题

3. **设计内容结构**
   → 调用 `Content-Architect` 构建母内容
   → 生成完整结构蓝图

4. **完成内容创作后**
   → 调用 `Content-Build` 裂变内容
   → 生成多种形式和平台的可分发内容
